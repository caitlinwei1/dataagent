# 退款分析报告：2026年2月 vs 2026年1月成功退款归因分析

## 1. 执行摘要

- **总体趋势**：2026年2月成功退款总金额为 **92,227.87 元**，较2026年1月的 **130,390.30 元** **下降 29.27%**（变化量：−38,162.43 元）  
- **最大降幅原因**：`NO_REASON`（无理由退款）单月减少 **43,311.92 元**（−78.3%），是整体下降的最主要驱动因素（贡献度 113.5%）  
- **次高降幅原因**：`DAMAGED`（商品破损）下降 3,174.58 元（−47.9%），`STOCKOUT`（缺货）下降 6,455.29 元（−22.2%）  
- **唯一上升原因**：`LATE_DELIVERY`（延迟发货）微增 113.10 元（+0.7%），但绝对增量极小，未改变整体下行趋势  
- **关键限制说明**：受数据上下文约束，**商品一级类目维度不可用**（无 `trd_item`、`dim_category` 表及关联字段），本次分析仅基于可验证的 `reason_code` 维度完成归因

## 3. 数据分析过程

### 3.1 查询逻辑（SQL）

**2026年1月退款汇总（Step 2）**：
```sql
SELECT 
  reason_code,
  SUM(refund_amount) AS refund_amount_sum
FROM trd_refund
WHERE 
  refund_status = 'SUCCESS'
  AND refund_time >= '2026-01-01' 
  AND refund_time < '2026-02-01'
GROUP BY reason_code;
```

**2026年2月退款汇总（Step 1）**：
```sql
SELECT 
  reason_code,
  SUM(refund_amount) AS refund_amount_sum
FROM trd_refund
WHERE 
  refund_status = 'SUCCESS'
  AND refund_time >= '2026-02-01' 
  AND refund_time < '2026-03-01'
GROUP BY reason_code;
```

### 3.2 归因计算逻辑（Python 合并与推导）

- 将两月结果按 `reason_code` 左连接（确保全量原因覆盖）  
- 计算：  
  - `change_amount = feb_refund - jan_refund`  
  - `change_rate = change_amount / jan_refund`（若 `jan_refund = 0`，则 `change_rate = null`）  
- 按 `|change_amount|` 降序排序，取 Top 5  
- 汇总全局变化：`total_feb - total_jan`

### 4.2 关键洞察

- **`NO_REASON` 断崖式下降是核心信号**：单原因减少超4.3万元，占总退款下降额的113.5%（>100%），表明其他原因的下降/上升被其完全主导。这**极可能反映政策调整**（如收紧七天无理由退货条件、增加审核环节、或促销活动结束导致冲动退货减少）。  
- **供应链相关原因同步改善**：`STOCKOUT`（−22.2%）、`DAMAGED`（−47.9%）、`WRONG_ITEM`（−74.0%）均显著回落，指向**仓配履约质量提升**。  
- **`QUALITY` 问题仍突出**：虽环比下降43.4%，但仍是2月第二大退款原因（¥13,289.78），且绝对值高于 `STOCKOUT` 和 `LATE_DELIVERY`，需持续关注品控。  
- **`LATE_DELIVERY` 基本持平**：微降0.7%，说明物流时效稳定性较好，未成为新风险点。
