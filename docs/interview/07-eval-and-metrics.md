# 07 320 题问数评测集 + 指标（SQL 执行成功率 / 多步完成率 / 报告耗时 vs 人工）

## 一句话讲法

> "我自己建了 320 题的评测集：80 个题族 × 4 组参数，每题的标准 SQL 都在库上跑过；按题族和月份切成 dev 192 / holdout 128，防止泄题。比的是执行结果不是 SQL 文本。每题一个 conversationId，完整 SSE 流存成 trace，能还原计划、每次 SQL、守卫和修复。因为额度只跑了 40 题配对样本：执行成功率 86.7→100%，EX 50.0→56.7%。"

## 1. 原来有什么问题

前面每一步只有局部指标（召回、守卫用例、沙箱用例），但用户只关心"问一句话拿到的数对不对"。需要回答：
1. 端到端成功率多少？卡在哪一环？
2. 每处改动到底贡献多少？
3. 会不会对着评测集调参？

## 2. 怎么做的

- **出题** `eval/nl2sql/build_questions.py` → `questions.jsonl`
  - 80 个题族（问题模板 + 标准 SQL 模板）× 4 组参数（月份、大区、类目、平台、仓库、N）。
  - 任务类型：单表 96 / 多表 96 / 多轮 64 / 多步 64；意图 5 类（TopN、聚合、对比、趋势、下钻）各 64。
  - 每条标准 SQL 在 MySQL 上执行：不能为空；TopN 并列时把并列行都记下。
  - **切分**：dev 192（2026-02/03 的题族）/ holdout 128（2026-04 的题族），题型和时间都不重叠。
- **运行** `eval/scripts/run_nl2sql.py`，配置入口 `scripts/step7/run_eval.sh {upstream_recall,v1,v2} {dev,holdout}`
  - 每题一个新 threadId（= conversationId）；多轮题先在同一会话问完前几轮，只给最后一轮打分。
  - SQL 类题走 `nl2sqlOnly`；多步题走完整流程、关闭人工审核。
  - 每题存完整 SSE 流，抽取：计划步数和工具、每次 SQL、每次守卫拦截和错误分类、最终结果集、总耗时和首字时间。
- **配对对比** `scripts/step7/run_sample.py` + `start_pair.sh`：两个后端（:8065 v2、:8066 只关掉新召回和 step7 修复）**同一题、同一模型并排跑**。
- **打分**：EX（执行结果比对），对列名、列顺序、取整、标签写法宽容；TopN 只看实体；另报严格版。

## 3. 为什么这么做

| 决策 | 选择 | 备选 | 为什么没选 |
|---|---|---|---|
| 判对错 | EX 结果比对 | SQL 文本 Exact Match | 同一问题多种正确写法（明细表 vs 日汇总表、JOIN vs 子查询） |
| | | LLM 裁判 | 不稳定、花 token |
| 题从哪来 | 人写模板 + 参数，逐条执行验证 | LLM 批量出题 | 标准 SQL 本身可能错，还带生成模型的偏好 |
| | | Spider / BIRD | 测不出本场景的口径、术语、跨域 |
| 切分 | 按题族 + 月份 | 随机 | 同模板 4 个变体会同时出现在两边 = 泄题 |
| 前后对比 | 两后端配对并排 | 先跑一套再跑另一套 | 中途额度用完换了模型，前后两段就不可比 |

**简历占位数字的处理**：
- 320 题完整结果：**没有**。补跑：`scripts/step7/run_eval.sh v2 dev` 然后**只跑一次** `scripts/step7/run_eval.sh v2 holdout`（支持断点续跑）。

- conversationId 串联：**有**，每题 trace 落盘，这一条可以放心讲。

## 6. 追问

1. **怎么防止对着评测集调参？** 题族+月份切分；修复只来自 dev 冒烟的 3 道题，那些题已从样本排除；holdout 只跑一次。
2. **执行成功率和 EX 为什么差这么多？** 能执行≠对，剩下的错基本都是口径（第 4 节）。光看执行成功率会高估系统。
3. **为什么只跑了 40 题？** 免费额度用完。方法和工具链完整，规模化数字在补；脚本断点续跑，一条命令。
4. **40 题的差异显著吗？** 不一定。step10 里同一配置跑两次就有 6/23 题翻转，所以 ±3 题以内不算数。执行成功率 86.7→100 方向明确，EX 50→56.7 只能说"方向一致"。可以主动讲这个噪声。
5. **多轮题怎么评？** 同一 threadId 先问前几轮，只评最后一轮，前几轮的结果不打分。
