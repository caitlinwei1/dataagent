- 每个子目录都有 `summary.json`，记录 threadId、每轮经过的节点、计划和审核提示。
- 另有逐条 SSE 事件的 `*.jsonl`。

**怎么核对**
- **修改**：把计划第 1 步的指令追加"只统计华东大区"，并删掉其余步骤，然后提交。执行的就是这 1 步，生成的 SQL 带 `big_region = '华东'`，见 `edit/2_edit.jsonl`。原版没有修改功能，同样的请求会照常执行原计划，SQL 里是全部 7 个大区。
- **连续驳回**：每次重新规划后，计划的思路说明都同时满足之前所有的驳回意见。第 2 次是"按省份 + 同比"，第 3 次是"按省份 + 同比 + 天猫"，见 `reject/summary.json`。原版只把最后一条意见交给规划器。
- **上限**：原版在这一步会抛出 `GraphRunnerException: cannot find edge mapping for id ... 'END'`。修复前的日志里见过这条报错，记录没有保存。
- **MySQL 断点**：存在元数据库的 `GRAPH_CHECKPOINT` / `GRAPH_THREAD` 两张表里。

确认和修改两条记录，是在"保留历次驳回意见"这个改动之前的版本上跑的。这两条流程不经过驳回分支，所以不受影响。
